AI-powered Learning Meter

Speaking and writing activities for children learning English, marked by AI against a teacher’s rubric. A wrong “well done” teaches the wrong thing, so the work was mostly about trust: rubrics, anchor answers, a test set, and an evaluation loop run before anything went live.

The rubric I wrote

Four bands, each with anchor answers for every activity

The model never scored against “good English” in general. For every mini-activity it got the question, what to check, and a real example answer at each band. It could choose any score from 20 to 100, but was anchored to these four.

Evaluation before launch

Did it get more trustworthy?

Every change was tested against a set of ≈4,000 answers with known scores before it reached a child: ≈1,300 real answers, plus ≈2,700 synthetic ones I wrote to cover the edge cases real data was thin on (other languages, fragments, near-misses). Each answer was graded twice to check the model gave the same score both times.

Design decisions

What I decided, and why

Feedback in ten words or fewer, spoken to an 8-year-old

Feedback is read mid-game by children around 8, so it’s short, in the first person, names the fix, and stays strict on the score.

Anything not in English scores 0

A correct idea in another language is still a miss in a language course, so it became a hard rule in every prompt.

Reuse scores for answers already seen

Children give many of the same answers. Cleaning up and matching them first made scoring instant, cheaper and consistent: the same answer always gets the same score.

One Learning Meter call per skill

If an activity tests grammar and vocabulary, each skill is scored against its own rubric, so feedback can say what to fix.

Low-creativity model settings

Grading must be repeatable. Every answer was scored twice in testing to catch drift between runs.

Humans stay in the loop

Flagged answers were reviewed and corrected in the test set, so the rubric and examples kept improving after launch.
